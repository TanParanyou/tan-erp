- Backend Integration `FinanceEndpointsTests` 5/5 บน PostgreSQL: **วงเงินสัญญา** (ยอด 125,000.50, ออกซ้ำ replay, payload ต่าง 409, เกินวงเงิน 422, ใบที่ void คืนวงเงิน, void ต้องมีเหตุผล/ตรวจ version, ใบที่ void รับชำระไม่ได้, สรุปโครงการ), **ยิงพร้อมกัน 4 คำขอ × 50,000 ต่อสัญญา 125,000.50 → สำเร็จพอดี 2**; **รับชำระ** (บางส่วน, เกินยอดค้าง, อ้างอิงซ้ำ, วันอนาคต, วิธีผิด, ทศนิยมเกิน, replay/ชน Key, ครบ → paid, void ไม่ได้เมื่อมีเงินรับ, กลับรายการแล้วยอดค้างกลับมา และกลับซ้ำไม่ได้, อ้างอิงที่กลับรายการแล้วใช้ซ้ำไม่ได้, **ยิงรับชำระพร้อมกัน 4 × 10,000 ต่อ 20,000 → สำเร็จพอดี 2 ไม่รับเกิน**); **outbox** (หนึ่งข้อความต่อเหตุการณ์, ระบบบัญชีล่ม → failed/backoff/ไม่ประมวลผลก่อนครบกำหนด, ครบ 5 ครั้ง → dead, requeue, exception เก็บเฉพาะชื่อชนิด (ไม่รั่วข้อความ), requeue ของรายการ pending ถูกปฏิเสธ, เมื่อระบบกลับมาส่งสำเร็จพร้อม envelope ที่มี snapshot/ dedupeKey/ reference hash, callback ยืนยันซ้ำคืนผลเดิม/ต่าง 409/ข้อมูลผิด 422, **ยอดที่บัญชียืนยันไม่ตรงปรากฏเป็น `amount_mismatch`**, `awaiting_confirmation` หายเมื่อยืนยัน, ไม่มี `missing_message`, void สร้างข้อความของตัวเอง, สิทธิ์ 403, ตัวกรองผิด 422); และ connector เริ่มต้นไม่เคยรายงานสำเร็จ. รวมชุด OpenAPI/DocumentSequence/Inventory ผ่าน.
- Frontend Vitest `features/finance` (สถานะ/ข้อความ th-en ครบ รวม outbox kind ที่เป็นชื่อมีจุด; รับชำระส่งเฉพาะข้อมูลที่ถูกต้องพร้อม Idempotency-Key; error แปลแล้วเมื่อเกินยอดค้าง; void เฉพาะเมื่อยังไม่มีเงินรับ และกลับรายการต้องมีเหตุผล; หน้าซิงก์แสดงคำเตือนว่ายังไม่เชื่อมระบบบัญชี, ผล retry, mismatch, requeue เฉพาะ failed/dead, ซ่อนปุ่มตามสิทธิ์), `tsc --noEmit`, `eslint .` ผ่าน.

## ข้อจำกัด

ค่าเริ่มต้นรอ Finance ยืนยัน: ไม่มีภาษี/ใบกำกับภาษี/หัก ณ ที่จ่าย/retention/ใบลดหนี้, ไม่มีวงเงินเครดิตลูกค้า (credit terms เดิมไม่เท่ากับ credit exposure control), ไม่มีเงินรับเกิน/การจัดสรรข้ามใบ, Change Order ไม่เพิ่มวงเงินวางบิล, ไม่มีระบบบัญชีจริง (connector ที่มีจริงมีเพียง placeholder ที่ไม่ส่งสำเร็จ จึงยังไม่ได้ทดสอบ outage/ซ้ำ/callback กับระบบจริง), ไม่มีตัวกำหนดเวลา (job) เรียก dispatch อัตโนมัติ — ต้องกดหรือให้ scheduler เรียก endpoint, callback ยืนยันเรียกด้วยผู้ใช้ภายในที่มีสิทธิ์ (ยังไม่มี webhook สาธารณะพร้อมลายเซ็น), ไม่ได้ทดสอบ dispatch พร้อมกันหลายตัว (อาศัย `SKIP LOCKED`), ไม่ได้รัน full Integration suite, `next build`, Playwright; ต้องมอบ 5 สิทธิ์ใหม่ (`billings.*`, `payments.manage`, `finance-sync.*`) ให้ Role จริง.
