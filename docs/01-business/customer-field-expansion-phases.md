# Customer Progressive Data Collection Specification (ข้อกำหนดการขยายข้อมูลลูกค้าตามระยะการทำงาน)

**สถานะ:** Proposed Business & Technical Direction (Baseline สำหรับ Phase ขยาย CRM)  
**ขอบเขต:** โมดูล CRM / ลูกค้า (Customer), ผู้ติดต่อ (Contact), ข้อมูลภาษี (Tax & Billing), สถานที่หน้างาน (Site)

---

## 1. ปรัชญาและเป้าหมายการออกแบบ (Design Philosophy & Purpose)

ในธุรกิจ**ออกแบบ ตกแต่งภายใน และผลิตงานเฟอร์นิเจอร์บิวต์อิน (Interior Design & Built-in Furniture)** วงจรชีวิตของลูกค้ามีปฏิสัมพันธ์กับหลายฝ่าย ตั้งแต่ฝ่ายการตลาด เซลส์ ดีไซเนอร์ ช่างสำรวจหน้างาน ฝ่ายจัดซื้อ และฝ่ายบัญชีการเงิน

- **ปัญหาของการบังคับกรอกข้อมูลทั้งหมดตั้งแต่แรก (High Friction):**  
  หากหน้าสร้างลูกค้า (`/customers/create`) บังคับกรอกเลขประจำตัวผู้เสียภาษี 13 หลัก, ที่อยู่ตาม ภ.พ.20, หรือรายละเอียดบริษัททั้งหมด จะทำให้พนักงานขายหรือดีไซเนอร์ที่รับ Lead เข้ามาเบื้องต้น (ผ่านโทรศัพท์, LINE หรือหน้าร้าน) ไม่สามารถบันทึกข้อมูลได้ทันที ทำให้เกิดการตกหล่นของ Lead
- **ปัญหาของข้อมูลไม่ครบเมื่อออกเอกสารทางการค้า (Compliance & Billing Gap):**  
  หากระบบไม่กำหนดขั้นตอนให้เก็บข้อมูลภาษีและที่อยู่ออกบิลก่อนออกใบเสนอราคา (Quotation) หรือใบกำกับภาษี (Tax Invoice) จะเกิดความผิดพลาดทางกฎหมายภาษีอากรและกระทบต่อฝ่ายบัญชี
- **แนวทางแก้ไข (Progressive Disclosure):**  
  ใช้หลักการ **"ทยอยเก็บข้อมูลตามความจำเป็นของแต่ละสถานะ (Gate-driven Progressive Collection)"** โดยแบ่งเป็น 4 ระยะ (Phases) ตามเส้นทางการทำงานจริง

---

## 2. การจัดแบ่งระยะการเก็บข้อมูล (Customer Data Collection Phases)

```text
[Phase 1: Quick Intake]       --> บันทึก Lead รวดเร็ว (Draft) ใน 30 วินาที
       │
       ▼
[Phase 2: Tax & Billing]       --> ข้อมูลนิติบุคคลและภาษีก่อนออกใบเสนอราคา/ใบแจ้งหนี้ (Active)
       │
       ▼
[Phase 3: Site & Operations]   --> สถานที่ติดตั้งหน้างานและข้อจำกัดอาคาร (Linked Sites)
       │
       ▼
[Phase 4: Commercial & Credit] --> วงเงิน เงื่อนไขเครดิต และประวัติการเงิน (Account Master)
```

---

### Phase 1: Quick Intake & Lead Capture (จังหวะสร้างลูกค้าใหม่ - Create Draft)

* **เป้าหมาย:** บันทึกตัวตนลูกค้าและช่องทางติดต่อเบื้องต้นให้เร็วที่สุด รองรับการใช้งานผ่านมือถือ/แท็บเล็ตหน้างาน
* **สถานะของข้อมูล:** `status = 'draft'`
* **ตำแหน่งหน้าจอ:** `/customers/create` (Single Dynamic Route `[id="create"]`)
* **รายการข้อมูล:**

| ช่องข้อมูล (Field) | ชนิดข้อมูล (Type) | ความจำเป็น (Gate) | คำอธิบายและกฎทางธุรกิจ |
| :--- | :--- | :--- | :--- |
| `customerType` | Enum | **บังคับ (D)** | `person` (บุคคลธรรมดา) หรือ `organization` (นิติบุคคล) |
| `displayNameTh` | String ≤250 | **บังคับ (D)** | ชื่อที่ใช้เรียก/แสดงผลภาษาไทย (Trim & Normalize ช่องว่าง) |
| `displayNameEn` | String ≤250 | ไม่บังคับ | ชื่อภาษาอังกฤษ (ไม่บังคับและไม่เดาคำแปลอัตโนมัติ) |
| `preferredLocale` | Enum | **บังคับ (D)** | ภาษาที่ลูกค้าสะดวก: `th` (ค่าเริ่มต้น) หรือ `en` |
| **Primary Contact** | Object | **บังคับ (D)** | ผู้ติดต่อหลักประจำลูกค้ารายนี้ (1 คนแรก) |
| ↳ `name` | String ≤250 | **บังคับ (D)** | ชื่อผู้ติดต่อหลัก |
| ↳ `roleTitle` | String ≤150 | ไม่บังคับ | ตำแหน่งหรือความสัมพันธ์ เช่น "เจ้าของบ้าน", "ผู้จัดการจัดซื้อ" |
| ↳ `phone` | String ≤30 | เงื่อนไข | อย่างน้อย Phone หรือ Email ต้องมีค่าอย่างใดอย่างหนึ่ง |
| ↳ `email` | String ≤150 | เงื่อนไข | Validate รูปแบบอีเมลที่ถูกต้อง |
| ↳ `lineId` | String ≤100 | **แนะนำเพิ่ม** | LINE ID ของผู้ติดต่อ (สำคัญมากสำหรับตลาดไทยในการส่งแบบ) |
| ↳ `preferredChannel`| Enum | **บังคับ (D)** | ช่องทางที่สะดวก: `phone`, `email`, `line`, `other` |
| **Lead Sourcing** | | | |
| ↳ `leadSource` | Enum/Code | **แนะนำเพิ่ม** | แหล่งที่มา: `walk_in`, `facebook_ads`, `referral`, `project_developer`, `website`, `other` |

### Phase 2: Commercial & Tax Readiness (จังหวะเตรียมความพร้อมทางการค้าและภาษี)

* **เป้าหมาย:** จัดเตรียมความพร้อมทางนิติกรรมและภาษีอากร ก่อนผ่านการอนุมัติใบเสนอราคาทางการ (Official Estimate/Quotation) หรือสัญญาจ้าง
* **สถานะของข้อมูล:** `status = 'active'` (ผ่าน Gate Activation)
* **ตำแหน่งหน้าจอ:** `/customers/[id]` (ส่วนจัดการ Tax & Billing Profile)
* **รายการข้อมูล:**

| ช่องข้อมูล (Field) | ชนิดข้อมูล (Type) | ความจำเป็น (Gate) | คำอธิบายและกฎทางธุรกิจ |
| :--- | :--- | :--- | :--- |
| `legalName` | String ≤250 | เงื่อนไข | ชื่อจดทะเบียนทางการตาม ภ.พ.20 หรือบัตรประชาชน (กรณีชื่อแสดงไม่ตรงกับชื่อจดทะเบียน) |
| `taxIdentifier` | String(13) | เงื่อนไข (A) | เลขประจำตัวผู้เสียภาษี 13 หลัก (ตรวจสอบ Check Digit; Mask ใน Log/Audit) |
| `branchCode` | String(5) | เงื่อนไข (A) | รหัสสาขาภาษี: `00000` (สำนักงานใหญ่) หรือเลขสาขา 5 หลัก เช่น `00001` |
| **Billing Address** | Sub-resource | เงื่อนไข (A) | ที่อยู่จดทะเบียนสำหรับออกใบกำกับภาษี/ใบเสร็จรับเงิน |
| ↳ `label` | String ≤100 | บังคับ | ป้ายระบุ เช่น "ที่อยู่จดทะเบียนสำนักงานใหญ่", "ที่อยู่ตามทะเบียนบ้าน" |
| ↳ `addressLine1` | String ≤250 | บังคับ | เลขที่, อาคาร, ชั้น, ซอย, ถนน |
| ↳ `subdistrict` | String ≤100 | บังคับ | ตำบล / แขวง |
| ↳ `district` | String ≤100 | บังคับ | อำเภอ / เขต |
| ↳ `province` | String ≤100 | บังคับ | จังหวัด |
| ↳ `postalCode` | String(5) | บังคับ | รหัสไปรษณีย์ 5 หลัก |
| ↳ `countryCode` | String(2) | บังคับ | ค่าเริ่มต้น `TH` |
| **Additional Contacts**| List | ไม่บังคับ | รายชื่อผู้ติดต่อเพิ่มเติม เช่น บัญชีการเงิน, วิศวกรโครงการ |

### Phase 3: Site & Operational Context (จังหวะสำรวจหน้างานและบริหารโครงการ)

* **เป้าหมาย:** แยกสถานที่หน้างานจริง (Job Site) ออกจากที่อยู่ของลูกค้าอย่างเด็ดขาด เพื่อรองรับกรณีลูกค้า 1 รายมีหลายหน่วยงาน/คอนโดหลายห้อง
* **ความสัมพันธ์:** 1 Customer มีได้หลาย Site (`1:N`)
* **ตำแหน่งหน้าจอ:** `/customers/[id]` (แท็บ Sites) หรือสร้าง Site ขณะเปิด Opportunity
* **รายการข้อมูล:**

| ช่องข้อมูล (Field) | ชนิดข้อมูล (Type) | คำอธิบายและกฎทางธุรกิจ |
| :--- | :--- | :--- |
| `label` | String ≤100 | ชื่อเรียกหน้างาน เช่น "คอนโด Ashton อโศก ชั้น 18 ห้อง 1802", "บ้านพักอาศัยราชพฤกษ์" |
| `structuredAddress` | Structured | ที่อยู่จริงของสถานที่ติดตั้ง (ตำบล/อำเภอ/จังหวัด/รหัสไปรษณีย์) |
| `latitude`, `longitude` | Decimal/null | พิกัด GPS หน้างานสำหรับช่างและทีมสำรวจ |
| `accessNote` | String ≤1,000 | **สำคัญสำหรับงานบิวต์อิน:** จุดจอดรถขนส่ง, ลิฟต์บริการ, ระเบียบเวลานิติบุคคลเรื่องเสียง/ฝุ่น, เบอร์นิติบุคคล |

### Phase 4: Financial & Relationship Terms (จังหวะสัญญาและการเงิน - Future Phase)

* **เป้าหมาย:** บริหารความเสี่ยงทางการเงินสำหรับลูกค้ารายใหญ่ ผู้รับเหมาหลัก (Main Contractor) หรือลูกค้านิติบุคคล
* **รายการข้อมูล:**

| ช่องข้อมูล (Field) | ชนิดข้อมูล (Type) | คำอธิบายและกฎทางธุรกิจ |
| :--- | :--- | :--- |
| `creditTermDays` | Integer | เครดิตเทอมชำระเงิน (วัน) เช่น 0, 15, 30, 60 วัน |
| `creditLimit` | Decimal/null | วงเงินสินเชื่อสูงสุดที่อนุญาตให้เปิดงานได้โดยไม่ต้องรอเคลียร์ยอดค้าง |
| `billingCycle` | Enum | รอบการวางบิล เช่น ทุกสิ้นเดือน, ทุกวันที่ 25 ของเดือน |
| `paymentConditionNote` | String ≤500 | เงื่อนไขการแบ่งงวดชำระ เช่น "งวดที่ 1 มัดจำ 50%, งวดที่ 2 เข้าติดตั้ง 40%, งวดที่ 3 ส่งมอบ 10%" |

## 3. สรุป Gate Legend และระดับการบังคับใช้

- **Gate D (Draft Intake):** ข้อมูลขั้นต่ำที่ระบบยอมรับเพื่อออกรหัสลูกค้า (`CUS-XXXXXXXXXXXX`) และเริ่มต้นบันทึกกิจกรรม
- **Gate A (Activation / Commercial Gate):** ข้อมูลที่ต้องกรอกครบก่อนสถานะเปลี่ยนเป็น `Active` เพื่อให้ออก Official Estimate หรือ Quotation ได้
- **Gate Q (Opportunity Qualified Gate):** ต้องมี Site และประเภทงาน (`workTypes`) ชัดเจนก่อนนัดสำรวจหน้างาน (Site Survey)

## 4. มาตรฐาน UI/UX (Atelier Architectural Navy Sharp Guidelines)

1. **หน้า Create (`/customers/create`):**
   - เรียบง่าย ไม่แบ่งแท็บลึก ใช้ฟอร์มแบบ Single Column หรือ Two-column Grid สบายตา
   - มีระบบตรวจจับชื่อซ้ำอัตโนมัติ (Duplicate Candidate Alert) ทันทีที่พิมพ์ชื่อหรือเบอร์โทรตรงกับลูกค้าเดิม
   - ไม่บังคับข้อมูลภาษีในหน้านี้ เพื่อให้ผู้ใช้สร้าง Draft ได้ภายในไม่เกิน 30 วินาที
2. **หน้า Detail & Edit (`/customers/[id]`):**
   - แบ่งหมวดหมู่ด้วยแท็บหรือ Card ที่ชัดเจน คม เหลี่ยม (`border-radius: 0px`)
   - **แท็บ 1: ข้อมูลทั่วไปและผู้ติดต่อ (Overview & Contacts):** ข้อมูลส่วนตัว, เบอร์โทร, LINE ID, ผู้ติดต่อสำรอง
   - **แท็บ 2: ข้อมูลภาษีและการออกบิล (Tax & Invoicing):** เลขประจำตัวผู้เสียภาษี, ชื่อ ภ.พ.20, รหัสสาขา, ที่อยู่จดทะเบียน
   - **แท็บ 3: สถานที่หน้างาน (Sites):** รายการ Site ทั้งหมดที่ลูกค้าเป็นเจ้าของ พร้อมปุ่ม "เพิ่มสถานที่หน้างาน"
   - **แท็บ 4: ประวัติงานขายและโครงการ (Opportunities & Projects):** งานทั้งหมดที่ผูกกับลูกค้ารายนี้
3. **การแสดงผลข้อความ (i18n Parity):**
   - ทุก Label, Placeholder, Error Text และ Tooltip ต้องมีคู่เทียบทั้ง `th` และ `en` ใน `messages/th.json` และ `messages/en.json`

## 5. ความปลอดภัย ข้อมูลส่วนบุคคล (PDPA) และ Audit Trail

- **Data Classification:**
  - `Personal Data`: เบอร์โทรศัพท์, อีเมล, LINE ID, เลขประจำตัวผู้เสียภาษี, พิกัดบ้านลูกค้า
  - `Customer-Safe Data`: ชื่อภาษาไทย, รหัสลูกค้า, ประเภทลูกค้า
- **Audit Logging Rule:**
  - เมื่อมีการแก้ไขข้อมูลผู้ติดต่อหรือข้อมูลภาษี ให้บันทึก Audit Event `customer.updated` หรือ `contact.updated`
  - **ห้ามบันทึกข้อมูล Personal Data ดิบ (เช่น เบอร์โทรจริง, เลขบัตร 13 หลัก) ลงใน Structured Log หรือ Error Details เด็ดขาด** ให้บันทึกเฉพาะ Field Name และ Changed Hash เท่านั้น
- **Permission Separation:**
  - การดูข้อมูลทั่วไปใช้สิทธิ์ `customers.read`
  - การดูเบอร์โทรและอีเมลแบบไม่ Mask ต้องใช้สิทธิ์ `customer-contacts.manage` (หากไม่มีสิทธิ์จะเห็นเป็น `081-XXX-XXXX`)
