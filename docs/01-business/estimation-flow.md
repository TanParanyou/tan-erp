# Estimation Flow (กระบวนการประเมินราคา)

**สถานะ:** Draft — เป็น Baseline มืออาชีพที่ต้องทดสอบกับเคสจริง

## เป้าหมาย

เปลี่ยนข้อมูลสำรวจและขอบเขตงานให้เป็นราคาที่ตรวจสอบที่มา อนุมัติ และออกใบเสนอราคาได้ โดยไม่ลบประวัติฉบับก่อนหน้า

## State Flow

```text
Draft → Ready for Review → In Review → Approved → Quoted
  │            │               │
  ├─ Cancelled └─ Returned ────┘
  └─ New Revision ← change after approval
```

## ขั้นตอนมาตรฐาน

1. เลือก Customer, Opportunity และ Site Survey
2. แบ่ง Scope เป็นพื้นที่หรือหมวดงาน เช่น Built-in, Electrical, Curtain
3. เพิ่ม Work Item จาก Item Master หรือรายการเฉพาะงาน
4. ระบุปริมาณ หน่วย ต้นทุนวัสดุ ค่าแรง ผู้รับเหมา และค่าใช้จ่าย
5. ระบบคำนวณต้นทุนรวม Markup/Margin ส่วนลด ภาษี และราคาขาย
6. ตรวจรายการที่ข้อมูลไม่ครบ ราคาหมดอายุ หรือกำไรต่ำกว่าเกณฑ์
7. ส่งอนุมัติตามวงเงินและเงื่อนไข
8. เมื่ออนุมัติแล้วจึงออก Quotation
9. หากมีการเปลี่ยนแปลงสาระสำคัญ ให้สร้าง Revision ใหม่และอนุมัติใหม่

## กฎขั้นต่ำ

- เงินเก็บเป็น Decimal พร้อม Currency ห้ามใช้ Floating Point
- Quantity ต้องมากกว่าศูนย์ และ Unit ต้องระบุ
- รายการที่ Override ต้นทุนหรือราคาต้องเก็บเหตุผล
- ผู้จัดทำห้ามอนุมัติรายการของตนเองเมื่อ Maker–Checker บังคับใช้
- Revision ที่อนุมัติแล้วเป็น Immutable Business Record
- Quotation หนึ่งฉบับอ้างอิง Estimate Revision เดียว

## ตัวอย่างสั้น

ตู้บิวต์อินยาว 3 เมตร มีวัสดุ 18,000 บาท ค่าแรง 7,000 บาท ค่าใช้จ่าย 2,000 บาท ต้นทุนรวมคือ 27,000 บาท ก่อนระบบใช้กฎ Markup/Margin และภาษีเพื่อหาราคาขาย กฎคำนวณจริงต้องยืนยันกับฝ่ายประเมินราคาและบัญชี

## Validation Questions

- บริษัทใช้ Markup หรือ Margin เป็นหลัก และปัดเศษระดับใด
- อนุมัติเป็นยอดรวม กำไรขั้นต่ำ ส่วนลด หรือหลายเงื่อนไขร่วมกัน
- ราคาวัสดุมีวันหมดอายุและ Supplier ที่เลือกหรือไม่
- ลูกค้าเห็นรายการต้นทุนละเอียดเพียงใด
- งานเพิ่ม–ลดหลังเปิด Project ใช้ Estimate Revision หรือ Change Order
